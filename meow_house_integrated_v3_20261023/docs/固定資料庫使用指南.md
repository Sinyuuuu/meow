# 固定資料庫使用指南

## 目前使用的資料庫

本專案目前使用 **SQLite**，不是 Supabase。網站所有版本共用的固定資料庫位置是：

```text
C:\Users\sinyu\Documents\Codex\MeowHouseData\app.db
```

各專案根目錄的 `.env` 必須包含：

```env
DATABASE_URL=sqlite:///C:/Users/sinyu/Documents/Codex/MeowHouseData/app.db
ROI_CONFIG_PATH=C:/Users/sinyu/Documents/Codex/MeowHouseData/rois.json
```

網站啟動時，終端機會印出實際資料庫位置。看到上述路徑才代表使用固定資料庫。

## 會永久保存的內容

- 會員、角色與登入帳號
- 貓咪資料
- 寄養資料與貓屋分配
- AI 區域活動紀錄
- 異常提醒與處理狀態
- 照護任務與照護留言
- 系統設定、裝置心跳與稽核紀錄

ROI polygon 座標不是資料表資料，但已集中存放在同一固定資料夾的 `rois.json`，切換專案版本時也會保留。

下列內容屬於執行中狀態，重開網站後恢復是正常的：

- AI Monitor 的 ONLINE／OFFLINE
- 當前即時影格
- 尚未通過防抖門檻的候選區域
- 尚未完成的即時推論狀態

## 每天怎麼使用

1. 雙擊 `啟動網站.bat`。
2. 查看終端機的「固定資料庫」是否為上面的固定路徑。
3. 從網站新增的資料會由 FastAPI／SQLAlchemy 自動寫入，不需要手動按資料庫儲存。
4. 停止網站時，優先在終端機按 `Ctrl+C`，再關閉視窗或電腦。

## 檢查資料庫

雙擊：

```text
database_status.bat
```

正常結果應包含：

```text
Integrity: ok
users: ...
pets: ...
activity_records: ...
care_logs: ...
```

## 建立備份

雙擊：

```text
database_backup.bat
```

備份會建立在：

```text
C:\Users\sinyu\Documents\Codex\MeowHouseData\backups
```

這個工具使用 SQLite 的線上備份功能，會正確包含 WAL 中已提交的資料。不要在網站執行時只複製 `app.db`，否則可能漏掉仍在 `app.db-wal` 的最新紀錄。

建議在以下時間建立備份：

- 大幅修改資料表之前
- Demo 前一天
- Demo 當天開始前
- 匯入大量測試紀錄後

## 切換或更新專案版本

新的專案版本只要把 `.env` 的 `DATABASE_URL` 設為相同固定路徑，就會看到同一份資料。不要把舊專案內的 `database/app.db` 覆蓋到固定資料庫。

## 如何復原備份

復原前必須先停止網站。請不要直接覆蓋；先將目前的 `app.db` 改名保留，再把選定備份複製成 `app.db`。如果不確定，先請 Codex 協助檢查備份日期與資料筆數。

## Supabase 是什麼時候需要

SQLite 適合目前單一電腦、單一網站程序的 Prototype。需要下列能力時，再考慮遷移到 Supabase PostgreSQL：

- 多台電腦同時使用
- 網站部署到雲端
- 校外遠端連線同一份資料
- 多店家或多房間長期營運

切換 Supabase 前需要先建立專案、取得 PostgreSQL 連線字串、加入 PostgreSQL driver，並做一次正式資料遷移；只改網址不會自動搬走 SQLite 既有資料。
